# МЕРА — бот учебной нагрузки в MAX

## Автоматическая оценка времени

Задайте `DEEPSEEK_API_KEY` в переменных окружения Bothost или в локальном `.env`. Бот использует DeepSeek Flash через `POST https://api.deepseek.com/chat/completions`. В запрос входят предмет, текст домашнего задания и номер класса, если он распознан из названия. Используйте описания заданий без персональных данных. [Документация DeepSeek](https://api-docs.deepseek.com/guides/json_mode/)

На шаге выбора времени учитель получает ориентир и вид работы. Для предупреждения о нагрузке учитывается число минут, которое выбрал учитель. При сбое сервиса доступен ручной ввод. Ключ хранится в настройках запуска.

## Mera Agent

Кнопка **Mera Agent** и команда `/agent` доступны участникам класса. Например, «Добавь 9А задание по алгебре к пятнице на 30 минут: решить № 12–15». Бот заполнит черновик, запросит пропущенные поля и покажет нагрузку до публикации. Изменения заданий и отметок используют те же проверки ролей и кнопки подтверждения, что обычное меню. Через агента также открываются нагрузка, задания и статистика, настройки класса, личный кабинет, план, выполненные задания и доступное время ученика.

Примеры для нескольких классов — «Покажи мои классы», «Открой 9А», «Покажи задания 8Б», «Покажи нагрузку всех классов», «Добавь классу новый предмет „Русский язык как иностранный“». Если в команде указан подключённый класс, агент открывает его перед выполнением. При совпадении названий бот предлагает выбрать класс кнопкой.

Частые команды и приведённый формат задания работают локально. Для свободной формулировки используется тот же `DEEPSEEK_API_KEY`. В запрос передаётся только текст команды без истории диалога, данных класса из базы и идентификаторов аккаунтов. Вводить личные данные или коды доступа в команды не следует. При недоступности распознавания остаются стандартные кнопки.

## Вход по ролям и предметы

При первом входе классный руководитель выбирает параллель и букву или вводит название класса. Бот создаёт отдельные коды для учителей и учеников. Учитель выбирает предмет из каталога для 1–4, 5–9 или 10–11 классов либо пишет своё название, затем вводит учительский код. Ученик вводит свой код после выбора роли.

«Личный кабинет» показывает роль, класс и предмет учителя. Классный руководитель видит предметы класса и число подключённых учителей по каждому из них. Руководитель и учитель могут добавить курс в список класса по названию, в том числе командой агенту «Добавь предмет Робототехника». Учителя, которые уже подключились раньше, могут выбрать предмет в кабинете.

В «Управлении классом» → «Ученики» классный руководитель видит список подключённых учеников, число отметок о выполнении по каждому заданию и выполненные задания отдельного ученика. Отображаемое имя можно задать в карточке ученика. Пока имя не указано, используется «Ученик 1», «Ученик 2» и так далее.

Кнопка «Инструкции» и команда `/help` открывают справку по текущей роли. В каждом разделе есть короткий порядок действий и переход к нужному экрану. Примеры команд Mera Agent собраны в отдельной теме.

На самих изображениях отображаются введённые данные: предмет, текст с номерами страниц и упражнений, срок и минуты. Перед публикацией показываются прежняя нагрузка, добавляемые минуты, сумма и превышение порога. В настройках времени рисуются выбранные минуты по дням; в завершённом задании — оценка, фактическое время и число выполненных заданий. При изменении данных формируется новый PNG и новый ключ кеша медиа MAX. Длинные тексты на изображениях сокращаются с многоточием; полный текст остаётся в подписи.

Первая версия для второго этапа конкурса. Дедлайн: **8 ноября 2026 года**.

Обновление интерфейса: каждый экран сопровождается фирменной графической карточкой. Нагрузка и личный план рисуются по реальным данным. После доставки новой карточки бот удаляет предыдущую свою карточку; пользовательские сообщения остаются. План и задания листаются кнопками внутри одного экрана. Дата выбирается через «Сегодня», «Завтра», ближайшие дни или календарь месяца. Минуты, предметы и доступное время также можно выбирать кнопками. Даты показаны по-русски, например «6 ноября, Пт». Короткий текстовый ввод `6.11`, `6 ноября` или `в пятницу` тоже поддерживается.

Реализованы роли администратора, учителя и ученика; создание класса и вход по разным кодам; добавление задания с предметом, текстом, сроком и минутами; проверка нагрузки до публикации; изменение срока или минут; недельная нагрузка; личный план с учётом времени ученика; отметки выполнения; добровольный ввод фактического времени; обезличенная медиана от трёх ответов; удаление заданий с проверкой прав.

Состояние диалога, задания и очередь ответов сохраняются в SQLite. Повторное получение одного события не публикует задание повторно. Ответы при сбое сети остаются в очереди. Если процесс оборвётся между доставкой сообщения и записью об этом в базу, текст ответа может прийти повторно; само задание не дублируется.

## Запуск без токена

Нужен **Python 3.11 или новее**. Для отрисовки карточек используется Pillow; шрифт Manrope с открытой лицензией включён в проект.

Откройте терминал в папке проекта:

```powershell
python -m pip install -r requirements.txt
python bot.py --demo
```

В демо вводите `/номер` для нажатия кнопки, например `/1` или `/2`. Обычные числа считаются текстовым вводом. Команды `/user 1`, `/user 2`, `/user 3` переключают тестовых пользователей. Кнопка «Сбросить демо» или команда `/reset_demo` после подтверждения очищает временную базу и открывает выбор роли. `/quit` завершает демо. Данные этого режима временные и не попадают в MAX.

Для повторяемого сценария со всеми ролями:

```powershell
python demo_scenario.py
```

В MAX нажмите **Демо-режим** в меню или кабинете либо отправьте `/demo`. «Аккаунты демо» переключают три тестовых аккаунта внутри вашей сессии. «Сбросить демо» после подтверждения очищает только эту тестовую базу и возвращает к выбору роли. «Выйти из демо» или `/demo_exit` возвращает к рабочим классам. Данные демо хранятся в памяти процесса и очищаются при перезапуске бота.

## Подключение конкурсного бота

1. В сообщении организаторов есть **одноразовая ссылка** на данные бота. Откройте её сами и сохраните данные локально. Эта программа не открывает ссылку и не запрашивает токен через чат.
2. Скопируйте `.env.example` в `.env`, если файла `.env` ещё нет.
3. В локальном `.env` заполните строку `MAX_BOT_TOKEN=`. Не публикуйте этот файл и не добавляйте его в архив для жюри.
4. Проверьте соединение:

```powershell
python bot.py --check
```

5. Запустите бота:

```powershell
python bot.py
```

6. Откройте конкурсного бота в MAX, нажмите «Начать», создайте класс. В «Управлении классом» получите отдельные коды учеников и учителей. Проверьте роль ученика и роль учителя с других аккаунтов MAX.

Компьютер должен оставаться включённым, а процесс — работающим. `Ctrl+C` останавливает бота, данные сохраняются. Для повторного запуска используйте ту же папку `data`.

Если бот запущен в фоне, его можно остановить из PowerShell в папке проекта: `& .\STOP-MAX.ps1`. Скрипт выбирает только процессы Python с абсолютным путём к `bot.py` из этой папки. Повторный одновременный запуск с той же базой блокируется, чтобы два процесса не забирали события друг у друга.

В этой версии используется **Long Polling для разработки и конкурсного показа**. MAX требует Webhook для production: [официальная документация](https://dev.max.ru/docs/chatbots/bots-coding/prepare/). Webhook и Long Polling одновременно использовать нельзя. Если у конкурсного бота уже есть Webhook-подписка, программа остановится и сообщит об этом, сохранив чужую настройку.

API: `https://platform-api2.max.ru`, токен передаётся в заголовке `Authorization`. При другом адресе API в инструкции организаторов укажите его в `MAX_API_BASE`. Для TLS-ошибок проверьте доверенные сертификаты и `SSL_CERT_FILE`; проверку сертификатов не отключайте.

На этом Windows-компьютере новый адрес не прошёл локальную проверку цепочки сертификатов. В рабочем `.env` выбран `https://platform-api.max.ru`: токен на этом официальном адресе принят, HTTPS проверяется штатно. Изменение касается только локальной настройки. Образец конфигурации сохраняет адрес из актуальной документации; при переносе настройте цепочку доверия нового адреса или проверьте доступность прежнего. Секретный `.env` в архив проекта не входит.

## Как считается нагрузка

- **Нагрузка класса**: сумма оценок времени по вечерам подготовки. Для новых заданий вечер вычисляется по дню урока. Отметка одного ученика не меняет нагрузку остальных.
- **Порог класса**: по умолчанию 180 минут, меняется администратором. Это демонстрационная настройка, не установленный норматив и не медицинская рекомендация.
- **Личный план**: невыполненные задания сортируются по ближайшему сроку, затем распределяются с сегодняшнего дня в доступное время ученика на ближайшие 7 дней. Большое задание может быть разбито на части.
- **Срок**: для нового задания учитель выбирает день урока, подготовка планируется до предыдущего вечера. Старые задания сохраняют прежний срок «до конца дня», без автоматического сдвига.
- **Нехватка времени**. Бот показывает, какую часть задания не удаётся выполнить к сроку. Просроченные задания выводятся отдельно. Срок автоматически не меняется.
- **Учёт выполнения**. «Часть выполнена» уменьшает остаток задания, «Выполнено» отмечает выполнение всего задания. Минуты записываются на день отметки и вычитаются из бюджета этого дня. Пока фактическое время не указано, используется оценка. Добровольный ввод времени за всё задание уточняет остаток на день завершения. Учитель видит медиану только от трёх ответов, без имён и ID.
- **Отмена**: ошибочное завершение отменяется в «Выполнено»; последняя частичная отметка — прямо из плана. Отмена завершения сохраняет ранее выполненные части. Удаление задания учителем не возвращает уже потраченное учеником время.
- **На сегодня**: можно изменить бюджет только текущего дня, сохранив обычное расписание на остальные дни. Уже учтённая работа вычитается из выбранного бюджета.
- **Редактирование**: учитель исправляет собственное опубликованное задание, администратор — любое задание своего класса. Изменяется существующая запись; одновременные правки не перезаписываются молча. Если задание уже выполнено учениками, перед сохранением сообщается, что их отметки сохранятся.
- **Быстрый ввод и повтор**. «Быстрый ввод» сохраняет предмет и предлагает ввести новый текст. «Повторить» использует текст предыдущего задания. В обоих случаях нужно выбрать день урока и подтвердить публикацию.
- **Полнота данных**. План отдельно показывает отсутствие добавленных заданий и выполнение всех добавленных заданий.
- **Перепроверка перед публикацией**: если другой учитель успел увеличить нагрузку выше порога, бот повторно показывает предупреждение.

## Команды

| Команда | Действие |
| --- | --- |
| `/start`, `/menu`, `/cancel` | Главное меню; отмена текущего ввода |
| `/help` | Объяснение расчёта и сроков |
| `/add` | Добавить задание, учитель/администратор |
| `/load` | Нагрузка класса на 7 дней |
| `/plan` | Личный план ученика |
| `/tasks` | Задания и обезличенная статистика, учитель/администратор |
| `/profile` | Личный кабинет и предметы класса |
| `/classes` | Мои классы, выбор активного класса и вход по коду |
| `/class` | Коды и порог, администратор |
| `/id` | Собственный ID пользователя |

Аккаунт может состоять в нескольких классах. Роль, предмет учителя и заготовки заданий хранятся отдельно для каждого класса. Смена кодов отзывает старые приглашения, а участники сохраняют доступ. Учительский код нельзя раздавать ученикам.

Бот обрабатывает задания и личные планы в **личных диалогах**. Хранятся ID в MAX, роли, задания, настройки времени и отметки выполнения. Отображаемое имя ученика задаёт классный руководитель для своего класса. Имя из профиля MAX, телефоны и контакты автоматически не импортируются. База и её резервные копии должны оставаться у владельца бота.

## Проверки

```powershell
python -m unittest discover -s tests -v
```

Проверяются предупреждения, перенос срока, повторное подтверждение, изменение нагрузки другим учителем, личные отметки, изоляция классов, права ролей, медиана, ограничения планировщика, повтор событий, очередь при сбое сети и перезапуск базы. Отдельная проверка в настоящем MAX требует локально настроенного токена.

## Docker

Если Docker установлен, после заполнения `.env`:

```powershell
docker compose up -d --build
docker compose logs -f
```

Данные находятся в томе `mera-data`. Для остановки: `docker compose down`. Не добавляйте `--volumes`, чтобы сохранить данные. Контейнер запускает тот же демонстрационный Polling; для постоянной эксплуатации потребуется Webhook.

Локальный Docker не был проверен в этой среде: Docker здесь отсутствует.

## План до сдачи

| Дата | Работа |
| --- | --- |
| 5 ноября | Локальная версия, проверка основных сценариев |
| 6 ноября | Подключение токена, проход учитель → ученик в MAX с реальными аккаунтами |
| 7 ноября | Проверка командой, оформление сообщений и запись демонстрации |
| 8 ноября | Повторная проверка запуска и сдача по требованиям конкурса |

Демонстрационные числа, включая пример 250 минут, не являются результатами пользовательского исследования. Интеграция с электронными дневниками, автоматическое определение минут из свободного текста, уведомления по расписанию и реальные метрики пилота в эту версию не входят. Даты и минуты вводит учитель.

## Файлы

- `mera.py` — расчёты, база, роли и диалоги.
- `workflows.py` — сроки к уроку, дневной учёт времени, частичные отметки, отмена, редактирование и быстрый ввод.
- `bot.py` — подключение MAX, очередь ответов и локальное интерактивное демо.
- `cards.py`, `assets/` — динамические инфографики, примеры карточек и шрифт с лицензией.
- `demo_scenario.py` — повторяемый сценарий показа без токена.
- `tests/` — автоматические проверки.
- `.env.example` — пустой образец локальной конфигурации.
- `Dockerfile`, `compose.yaml` — контейнерный запуск.
- `START-DEMO.cmd`, `START-MAX.cmd` — запуск двойным щелчком на Windows.

Источники формата API: [сообщения](https://dev.max.ru/docs-api/methods/POST/messages/), [кнопки](https://dev.max.ru/docs-api/use-cases/sending-messages/keyboard/), [Long Polling](https://dev.max.ru/docs-api/methods/GET/updates/).
